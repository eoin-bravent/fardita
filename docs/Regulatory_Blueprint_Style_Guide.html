The Regulatory Blueprint system

A documentation aesthetic for dense technical and governmental material: navy ink on warm paper, a brass authority accent, and a signal-cyan accent for movement and cross-reference. This page is built with the system it describes — every component below is live, paired with the markup to reproduce it.

3 typefaces 2 accents 14 components light · print-ready
00

Philosophy

One structure, two accents

The system is built for long, reference-grade documents that must stay readable and printable. It pairs a serif display face with a humanist body face and a monospace utility face, on a warm paper ground rather than stark white. Structure is carried by monospace eyebrows and numbered section markers — used only where the content genuinely is a sequence — and by hairline rules, never by heavy chrome.

The discipline that keeps it coherent is the two-accent rule. Each accent has one job and they never blur:

Brass — authority
Structure & weight

Section numbers, eyebrows, list markers, citations, high priority, the canonical "rule" callout. The voice of the source and its hierarchy.

Signal — motion
Movement & reference

Cross-links, complexity notes, the "note" callout, secondary states, anything that points elsewhere or is in flux. The voice of the system reasoning over the source.

Rule of thumb. If you are about to use both accents on the same element, stop — pick the one that names the element's job. Brass for what a thing is; signal for where it goes or how it changes.

Typography

Three faces, fixed roles

Load all three from Google Fonts. Fraunces (display serif) sets h1 and the section-name h2. Public Sans — the USWDS body face — carries all running text, h3, the .lede subhead, and the .rule callout. IBM Plex Mono is the utility face for eyebrows, section numbers, labels, captions, and data.

Page skeleton

Layout shell

The page is a two-column grid: a sticky 280px navigation rail and a fluid main column capped at 920px for comfortable measure. On screens under 880px the rail drops above the content and the TOC becomes a horizontal row. This is the entire frame — drop your sections inside <main class="main">.

<body>
<div class="shell">
  <aside class="rail">
    <div class="brand">
      <div class="seal">FAR</div>
      <b>Document title<small>Subtitle</small></b>
    </div>
    <nav><ul class="toc" id="toc">
      <li><a href="#s1"><span class="n">01</span> First section</a></li>
    </ul></nav>
    <div class="meta"><div><b>Key</b> · value</div></div>
  </aside>

  <main class="main">
    <header class="doc-head"> ... </header>
    <section id="s1"> ... </section>
  </main>
</div>
<!-- scroll-spy script at end of body (see §15) -->
The seal. The circled three-letter mark in the rail is the system's wordless signature — a dashed inner ring evoking an official stamp. Keep it to three characters.
04

Section headers

Numbered section heads

Each section opens with a small monospace .sec-num marker (just the number) and a trailing hairline, then the section name as a large h2, then an optional smaller .lede subhead for the descriptive line. The name is the headline; the descriptive phrase is supporting copy, not the main feature. Sections are divided by a top border automatically (section + section). Use numbers only when the document genuinely reads in order.

06

Callouts

Two callout voices

Callouts are left-bordered blocks. .note is signal-cyan for asides, caveats, and cross-references. .rule is brass and set in the body font at a larger size — reserve it for a single load-bearing principle per section.

Note. A signal-cyan aside — secondary information, a caveat, or a pointer elsewhere. Body weight, comfortable to skim past.
A brass rule in the body font, slightly larger — the one principle a section is built around. Used sparingly, it reads as the takeaway.
markup

.note → signal · skimmable
.rule → brass · one per section

Code blocks

Code & data blocks

The <pre> block is the one dark surface in the system — navy ink ground with cyan text. Three token spans color the syntax: .c for comments, <b> for keywords/identifiers (cyan), and .g for highlighted values (gold). In print, the block inverts to light automatically.

# comment via .c
def retrieve_context(query, acl):
    return db.run("""
        SELECT chunk_id FROM chunks
        WHERE acl_visible(:acl)      -- highlight via .g
        ORDER BY embedding <=> :qvec
    """)
<!-- the three token spans -->
<span class="c">comment</span>     → muted gold
<b>identifier</b>             → cyan
<span class="g">value</span>       → gold

Usage principles

Keeping it coherent

  1. Reference tokens, not values. Every color and font comes from a var(--token). To re-theme, edit :root once.
  2. Hold the two-accent line. Brass = authority and structure; signal = motion and reference. Green (.pill.e) appears only for "low/easy/done." No other hues.
  3. Number only real sequences. Section markers and ordered lists imply order — use cards or plain headings when order doesn't matter.
  4. One .rule per section. The brass serif callout is the takeaway; more than one and it stops landing.
  5. Dark only for code. The navy <pre> is the single dark surface — it earns attention by being rare.
  6. Quiet around the signature. The rail seal and numbered heads carry the identity; keep everything else restrained.
Scroll-spy. The rail highlights the active section via this script at the end of <body>. It reads the TOC, so new sections need no wiring beyond a matching id.
<script>
(function(){
  const links=[...document.querySelectorAll('.toc a')];
  const secs=links.map(a=>document.querySelector(a.getAttribute('href')));
  const obs=new IntersectionObserver(es=>{
    es.forEach(e=>{ if(e.isIntersecting){
      const id='#'+e.target.id;
      links.forEach(a=>a.classList.toggle('on',a.getAttribute('href')===id));
    }});
  },{rootMargin:'-15% 0px -75% 0px'});
  secs.forEach(s=>s&&obs.observe(s));
})();
</script>
The throughline: warm paper, navy ink, one accent for authority and one for motion — structure carried by type and hairlines, boldness spent only on the signature.
